# GT SHOP KZ — демо интернет-магазина

Адаптивный статический каталог автомобильного тюнинга и аксессуаров.

## Текущее состояние
- Каталог объединяет вручную проверенные карточки и импортируемый список товаров JPM.
- Импортёр собирает карточки из категорий карты сайта, сохраняет оригинальные ссылки и фото, распознанные цены и дату импорта.
- Для запуска импорта открой GitHub → Actions → Import JPM catalog → Run workflow. Для локального запуска используй `node catalog-import/import-jpm.mjs` на Node.js 20+.
- Позиции 9–20 в ручной подборке остаются демонстрационными и помечены бейджем «Демо»; они не являются реальными предложениями продавца.

## Запуск
- Открой `index.html` в браузере.
- Для локального сервера используй VS Code + Live Server.
- Публикация: GitHub Pages из ветки `main`.

Цены в карточках — снимки каталога на момент проверки, не live-прайс. Наличие, стоимость, доставка и совместимость требуют подтверждения у продавца. Автоимпорт пока не заполнил каталог: при запросе из GitHub Actions JPM возвращает пустой HTML-шаблон без карточек товаров. Чтобы импортировать весь ассортимент, нужен разрешённый CSV/XML/JSON-фид или экспорт каталога. Скрипт не подставляет выдуманные товары.

## Backup
Полная резервная копия состояния сайта до расширения каталога: `backup/2026-10-28/`. В папке сохранены `app.js`, `index.html`, `styles.css` и копия всех файлов из `assets/`. Для отката скопируй резервные файлы обратно в корень репозитория. Данные корзины и избранного из localStorage не входят в резервную копию.

## Ограничения демоверсии
- Корзина и избранное хранятся в localStorage текущего браузера.
- Онлайн-оплата, серверный склад и синхронизация с продавцами не подключены.
- Не оформляй реальный заказ только на основании демонстрационной карточки.


## Firebase: облачные профили и гараж

Сайт пока работает как статическая демоверсия. По умолчанию профиль и гараж хранятся в localStorage. Для сохранения между устройствами подключи бесплатный Firebase:

1. Создай проект на https://console.firebase.google.com/ и добавь Web App.
2. В Authentication → Sign-in method включи **Email/Password**.
3. В Firestore Database создай базу в production mode.
4. Скопируй конфигурацию Web App в `firebase-config.js`, заменив все значения `PASTE_...` и `YOUR_PROJECT_ID`.
5. В Firestore Rules вставь содержимое `firestore.rules` и опубликуй правила.
6. В Firebase Authentication → Settings → Authorized domains добавь домен, на котором опубликован сайт (например, `david-nismo.github.io`).

После настройки пользователь сможет создать аккаунт/войти на странице «Профиль». Имя, email и выбранный автомобиль сохраняются в `users/{uid}`; правила запрещают доступ к чужим документам. Пароли сайт в Firestore не сохраняет — их обрабатывает Firebase Authentication.

Если конфигурация не заполнена, облачная авторизация скрыта, а локальный демо-режим продолжает работать. Firebase web config предназначен для клиента; безопасность обеспечивается правилами Firestore, а не секретностью API key.
